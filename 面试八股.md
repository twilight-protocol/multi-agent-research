## 一、Python 语言基础

| 问题                                    | 答案要点                                                                                                                                                  | 项目落点                                                                                             |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `list` 和 `tuple` 的区别？              | 可变 vs 不可变；tuple 可作 dict key、更省内存。                                                                                                           | 工具返回值用 str（不可变、可直接进消息）                                                             |
| 可变默认参数的坑？                      | `def f(x=[])` 默认值在函数定义时创建一次，多次调用共享同一对象 → 用 `None` 兜底。                                                                         | 无直接落点，但是高频考点                                                                             |
| 深浅拷贝区别？                          | 浅拷贝只复制第一层，嵌套对象仍共享引用；嵌套结构要 `copy.deepcopy`。                                                                                      | 构造检索结果列表时没改原文，属自然避免                                                               |
| 装饰器原理？                            | 接受函数返回新函数的高阶函数，`functools.wraps` 保留元信息。                                                                                              | `@tool` 本身就是装饰器（Q5 讲它在实例方法上失效）                                                    |
| 生成器是什么？为什么省内存？            | 函数体含 `yield` 即是生成器，惰性求值，不一次性构造全部结果。                                                                                             | SSE 的 `event_gen()` 就是 async generator，每次 yield 一帧                                           |
| `*args` / `**kwargs`？                  | 位置参数元组 / 关键字参数字典。                                                                                                                           | `ensure_conversation(thread_id, first_message="")` 用了默认参数                                      |
| `is` 和 `==` 区别？                     | `is` 比身份（内存地址），`==` 比值（可重载 `__eq__`）。                                                                                                   | 判断 `None` 必须用 `is`（`x is None`）                                                               |
| 列表推导 vs `map`？                     | 推导式更快更可读；`map` 惰性但需转 list。                                                                                                                 | 略                                                                                                   |
| GIL 是什么？影响？                      | CPython 全局锁，同一进程内同一时刻只有一个线程执行 Python 字节码；IO 会释放 GIL，所以 IO 密集多线程仍有效，CPU 密集要靠多进程。                           | 呼应「`to_thread` 能把阻塞调用甩出去正是因为 IO 释放 GIL」；纯 CPU 计算（PDF 解析）本质仍受 GIL 限制 |
| `BaseException` 和 `Exception` 的关系？ | `BaseException` 是根，`Exception` 是它的子类；`KeyboardInterrupt` / `SystemExit` / `CancelledError` 直接继承 `BaseException`，`except Exception` 抓不到。 | **台账 Q22 的核心**                                                                                  |
| 上下文管理器 / `with` 原理？            | 实现 `__enter__` / `__exit__`，或用 `@contextmanager`。                                                                                                   | `database.py` 的 `_connect()` 用 `@contextmanager` 保证 commit/rollback/close                        |
| `assert` 能用于生产校验吗？             | 不能——`-O` 优化模式下会被整段跳过。                                                                                                                       | 验证脚本里用 `assert` 是对的，生产代码用 `raise`                                                     |

## 二、Python 异步与并发

| 问题                                   | 答案要点                                                                             | 项目落点                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------- |
| 什么是协程？asyncio 怎么调度？         | 单线程事件循环 + 协作式调度；`await` 处主动让出控制权。                              | 全部路由                                    |
| `async def` 里调用同步阻塞函数会怎样？ | **阻塞整个事件循环**，所有并发请求一起卡住。                                         | 台账 Q17 的 B 组就是实证（2062ms 心跳间隔） |
| `asyncio.to_thread` 做了什么？         | 把同步函数丢到默认线程池执行，返回 awaitable；底层是 `loop.run_in_executor`。        | `chat.py` / `upload.py` 四处                |
| 为什么 `finally` 里不能再 `await`？    | 任务已被取消，在被取消的任务里 await 会立刻再抛一次 `CancelledError`。               | 台账 Q22                                    |
| 线程池有上限吗？                       | 默认 `ThreadPoolExecutor` 的 `max_workers = min(32, os.cpu_count() + 4)`。           | 讲「高并发会排队」时引用                    |
| 并发 vs 并行？                         | 并发是交替推进（可能单核），并行是物理同时执行（多核）。                             | 本项目是并发（IO 密集）                     |
| `async for` 和 `for` 区别？            | `async for` 遍历异步迭代器，每次迭代可能 await。                                     | 读 LangGraph 流                             |
| `asyncio.run()` 能调用多次吗？         | 每次新建并关闭一个事件循环；循环关闭后绑定它的客户端（如 httpx AsyncClient）就废了。 | 台账 Q20 最后一行踩坑                       |

| `StaticFiles(html=True)` 有什么用？       | 直接托管静态站，自动把 `/` 映射到 `index.html`。                                              | 页面与 API 同源，免 CORS、免 nginx                                                             |
| 启动时就该失败的错误怎么处理？            | 在模块顶层做校验并 `raise`，让进程起不来（fail fast），避免「页面打得开、一问就崩」。         | `main.py` 校验 `DASHSCOPE_API_KEY`                                                             |
| 状态码语义：400 / 401 / 404 / 429 / 500？ | 参数错 / 未认证 / 不存在 / 限流 / 服务端错。                                                  | 上传 400/500、限流 429、空会话刻意返回 200+`[]`（台账 Q23）                                    |

## 四、HTTP / SSE / 网络

| 问题                                                    | 答案要点                                                                           | 项目落点                                                   |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| SSE 的报文格式？                                        | `event: <名称>\ndata: <载荷>\n\n`，**空行代表一帧结束**。                          | 台账 Q12 第 1 点                                           |
| SSE 和 WebSocket 怎么选？                               | 单向服务端推送用 SSE（普通 HTTP、自带重连）；双向实时通信用 WebSocket。            | 聊天是单向输出，选 SSE                                     |
| 为什么 `EventSource` 用不了？                           | 浏览器原生 `EventSource` 只支持 GET，无法带 POST body。                            | 前端用 `fetch` + `ReadableStream` 手解                     |
| `TextDecoder` 为什么要 `{ stream: true }`？             | 一个 UTF-8 中文字符可能被切在两个 chunk 边界上，不保留状态会解出 `�`。             | `api/chat.js`、`api/research.js`                           |
| 分块传输怎么切帧？                                      | 按 `\n\n` 切，最后一段可能是不完整的半帧，要留在缓冲区 (`buf = frames.pop()`)。    | 同上                                                       |
| `Cache-Control: no-cache` 起什么作用？                  | 禁止中间层缓存响应，否则流式内容会被整体缓存后一次性吐出。                         | `chat.py` 响应头                                           |
| `X-Accel-Buffering: no` 是什么？                        | 告诉 nginx 不要缓冲响应体（否则流式会被攒成一大块）。                              | 同上；本项目单容器无 nginx，属零成本预防                   |
| `X-Forwarded-For` 为什么重要？                          | 应用前有代理时 `request.client.host` 拿到的是代理 IP，取真实 IP 必须读该头。       | `ratelimit.py` 的 `_client_ip()`                           |
| `Content-Type: application/json` 作用？                 | 告知解析格式；缺了后端可能按表单/纯文本处理。                                      | 前端 `fetch` 显式设置                                      |
| **手写 `Content-Type: multipart/form-data` 为什么错？** | 边界（boundary）由浏览器自动生成，手写会丢掉 boundary → 后端解析失败（实测 422）。 | 项目2 上传：字段名必须叫 `file`，且**不手写** Content-Type |

## 五、数据库

| 问题                           | 答案要点                                                                                                                                    | 项目落点                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 事务的 ACID？                  | 原子性 / 一致性 / 隔离性 / 持久性。                                                                                                         | `_connect()` 的 commit / rollback                                                   |
| 什么是索引？什么时候不该加？   | 加速查询但拖慢写入、占空间；低区分度列、频繁更新的列不宜加。                                                                                | `idx_messages_thread(thread_id, id)` 复合索引，正好服务「按会话取消息并按 id 排序」 |
| SQLite 的 WAL 模式是什么？     | Write-Ahead Logging：读不再阻塞写、写不阻塞读（写与写仍串行）。                                                                             | `PRAGMA journal_mode=WAL`（台账 Q16）                                               |
| 为什么 SQLite 连接不能跨线程？ | 连接对象有线程亲和性，跨线程用会报错，除非 `check_same_thread=False`。                                                                      | 台账 Q16 第 1 点                                                                    |
| `INSERT OR IGNORE` 语义？      | 主键/唯一约束冲突时忽略本次插入，不报错。                                                                                                   | 建会话时防止覆盖已有标题                                                            |
| 怎么取自增主键？               | `cursor.lastrowid`。                                                                                                                        | `add_message()`                                                                     |
| N+1 查询问题？                 | 循环里逐条查关联数据 → 改成 JOIN 或一次批量查。                                                                                             | 会话列表用相关子查询统计 `message_count`，一次请求拿到全部数据                      |
| **事务隔离级别（MySQL）**      | 读未提交 / 读已提交 / **可重复读（InnoDB 默认）** / 串行化；靠 MVCC + 间隙锁解决脏读、不可重复读、幻读。                                    | Day36 八股，项目里未用 MySQL，如实说                                                |
| **B+ 树为什么适合做索引？**    | 矮胖（3~4 层撑千万级）、非叶子结点只存键、叶子结点链表支持范围查询 → 比二叉树层数少、比哈希树支持范围。                                     | 同上                                                                                |
| **`EXPLAIN` 看什么？**         | `type`（访问类型，`ALL` 全表最差）、`key`（实际用的索引）、`rows`（预估扫描行数）、`Extra`（`Using filesort` / `Using temporary` 要优化）。 | 同上                                                                                |
| **Redis 怎么限流？**           | `INCR key` + `EXPIRE key 窗口秒`，超过阈值返回 429；或用滑动窗口（ZSET 存时间戳）。本项目用**进程内内存计数**，多副本即失效。               | 台账 §11.4、`ratelimit.py`                                                          |

## 六、RAG 原理

| 问题                               | 答案要点                                                                                                              | 项目落点                                    |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| RAG 完整流程？                     | 离线：加载 → 切块 → 向量化 → 入库；在线：query 向量化 → 检索 top-k → 拼 context → 交给 LLM 生成。                     | `ingest.py`（离线）+ `knowledge.py`（在线） |
| RAG 解决什么问题？                 | ① 把模型不知道的私有知识喂给它；② 让答案有出处可核查；③ 比微调便宜、可即时更新。                                      | 项目核心场景                                |
| RAG 和微调怎么选？                 | 知识频繁更新、要求可溯源 → RAG；要改变模型风格/能力/固定格式输出、且样本充足 → 微调。两者可叠加。                     | 面试标准答                                  |
| 切块 `chunk_size` 怎么定？         | 看文档密度：太小语义不全，太大检索精度下降。中文一般 300~800 字，本项目取 500。                                       | `ingest.py`                                 |
| `overlap` 有什么用？               | 保证跨块边界的语义不被切断（答案横跨两段时仍能召回）。代价是冗余。                                                    | 80（约 16%）                                |
| 中文 `separators` 为什么要补标点？ | 默认分隔符是英文体系（`\n\n`、空格），中文长句不会被切断。                                                            | 补了 `。！？；，`                           |
| 检索不准怎么办？                   | 分层：query 改写 / 混合检索（关键词+向量）/ rerank / 调切块 / 换 embedding 模型 / 加元数据过滤。                      | 改进方向答法                                |
| 怎么评估 RAG？                     | 检索侧：召回率 Recall@k、MRR、命中率；生成侧：忠实度（是否忠于 context）、答案相关性。需要固定评测集。                | 台账 Q21 的正负样本集就是最小评测集         |
| 幻觉怎么抑制？                     | ① Prompt 硬规则「只依据 context」；② 要求标注出处；③ 检索不到就明确说「未提及」；④ 降低 temperature；⑤ 检索阈值过滤。 | System Prompt 三条硬规则                    |
| 为什么回答要标页码？               | 可溯源 = 用户能自行验证，显著提升可信度；也是竞品常见缺失点。                                                         | 工具返回值带 `[文件名 第N页]`               |
| 上下文里放几块合适？               | `RAG_TOP_K=4`；太多会稀释注意力且涨 token 成本，太少会漏信息。                                                        | `config.py`                                 |

## 七、向量检索原理

| 问题                     | 答案要点                                                                                    | 项目落点                                          |
| ------------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Embedding 是什么？       | 把文本映射成高维稠密向量，语义相近的文本向量距离小。                                        | `text-embedding-v3`，1024 维                      |
| 余弦相似度 vs 欧氏距离？ | 余弦看方向（对长度不敏感，适合文本）；欧氏看绝对距离。归一化后两者单调相关。                | 讲清「Chroma 返回的是距离，越小越近」（台账 Q21） |
| 向量库的检索是暴力算吗？ | 小数据量暴力（flat）即可；大数据量用近似最近邻索引（HNSW / IVF / PQ）换速度、牺牲少量精度。 | 本项目数据量小（27 条），无需调索引               |
| top-k 和阈值的关系？     | 先按排序取 top-k，再按距离阈值过滤；两者是「候选数量」与「质量下限」的正交控制。            | `similarity_search_with_score(k=4)` + `s <= 0.8`  |
| 为什么必须做去重？       | Chroma 不做内容去重，同一份文件重复上传会导致检索结果里同一段出现多次，稀释 top-k 名额。    | 按 `source` 先删后加（台账 Q20）                  |

## 八、Agent / LLM 原理

| 问题                                   | 答案要点                                                                                                                     | 项目落点                                                                        |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Agent 和 RAG 的本质区别？              | RAG 是固定流程（检索→生成）；Agent 是**模型自主决策**要不要调工具、调几次、按什么顺序。                                      | 项目两者都有：RAG 是 Agent 的一个工具                                           |
| 什么是 ReAct？                         | Reasoning + Acting 交替：模型先输出思考、再决定动作、观察结果后继续，直到给出最终答案。                                      | `model ↔ tools` 循环就是 ReAct 的图化实现                                       |
| 模型是怎么「调用」工具的？谁在执行？   | 模型**只输出结构化意图**（`tool_calls`：函数名 + 参数 JSON），**真实执行永远在代码里**（`ToolNode`）。这是安全边界所在。     | `backend/ai/agent.py`                                                           |
| 工具描述（docstring）为什么重要？      | 它是模型做路由决策的**唯一依据**——描述模糊模型就判断不了该不该调（台账 Q8 的根因）。                                         | `search_knowledge_base` 的长 docstring                                          |
| `bind_tools` 做了什么？                | 把工具 schema 转成 OpenAI function calling 格式塞进请求，模型据此产生 `tool_calls`。                                         | `llm.bind_tools(ALL_TOOLS)`                                                     |
| 模型有记忆吗？                         | **没有**。多轮是每次把历史消息重新拼进 prompt；「记忆」是框架侧的状态管理。                                                  | 台账 Q13                                                                        |
| 什么是 checkpointer？                  | 状态持久化器，按 `thread_id` 存取完整对话状态，实现跨轮记忆与断点恢复。                                                      | 项目1 `InMemorySaver` → 项目2 `AsyncSqliteSaver`                                |
| temperature 作用？                     | 控制采样随机性：低=稳定保守（事实问答），高=发散（创意）。                                                                   | 事实类任务设 0.1~0.3；但**注意 `temperature=0` 也不保证完全确定**（台账 P2-Q1） |
| token 和成本怎么控？                   | ① 限制 top-k 与上下文长度；② 无效调用拦截（限流）；③ 简单问题不走上层模型；④ 会话历史截断/摘要。                             | 限流 + `RAG_TOP_K=4`                                                            |
| 怎么做链路追踪？                       | 记录每次模型输入输出（含 `thread_id`），按会话回放；LangGraph metadata 里的 `ls_*` 字段就是 LangSmith 追踪用的（台账 Q14）。 | —                                                                               |
| **为什么要「自审循环」+ 代码硬上限？** | Agent 会**自我欺骗**（判官持续要求改）→ 必须有**独立审查节点**，且循环上限由**代码**兜底，不能靠模型自己说停。               | 台账 §12.4、P2-Q1                                                               |
| **什么是 human-in-the-loop？**         | 图跑到某点用 `interrupt()` 挂起，外部给输入后用 `Command(resume=...)` 从断点续跑（不重跑前面节点）。                         | 项目2 `human_review_node`（台账 §12.4）                                         |

## 九、LangChain / LangGraph

| 问题                                    | 答案要点                                                                                                                                             | 项目落点                                              |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| LCEL 是什么？`\|` 背后是什么？          | LangChain Expression Language；`\|` 是 `Runnable.__or__`，把两个 Runnable 串成 `RunnableSequence`。                                                  | 项目1 未用 LCEL（用 LangGraph），但要知道             |
| Runnable 的常用方法？                   | `invoke` / `ainvoke` / `stream` / `astream` / `batch` / `bind`。                                                                                     | `astream` 是流式的关键                                |
| 消息类型有哪些？                        | `SystemMessage` / `HumanMessage` / `AIMessage` / `ToolMessage`（还有 `AIMessageChunk`）。                                                            | 流里按类型区分处理（台账 Q4）                         |
| LangGraph 比 LangChain 链强在哪？       | 链是线性 DAG；图支持**循环**（工具反复调用）、**条件边**（动态路由）、**状态**（reducer 合并）、**中断**（human-in-the-loop）。                      | 项目1 `model ↔ tools` 回边；项目2 六节点 + 三组条件边 |
| `StateGraph` 三个要素？                 | 状态（`MessagesState`/自定义 TypedDict）+ 节点（函数）+ 边（`add_edge` / `add_conditional_edges`）。                                                 | `agent.py`、`research/graph.py`                       |
| reducer 是什么？                        | 声明「新值如何合并进旧状态」。`add_messages` = 追加。                                                                                                | 台账 Q13 第 1 点                                      |
| `tools_condition` 做什么？              | 预置条件函数：检查最后一条 AIMessage 是否带 `tool_calls`，有就去 `tools` 节点，没有就 `END`。                                                        | `add_conditional_edges("model", tools_condition)`     |
| `ToolNode` 做什么？                     | 读取消息里的 `tool_calls`，执行对应工具，把结果包成 `ToolMessage` 写回状态。                                                                         | 工具真实执行处                                        |
| LangChain 1.x 和 0.x 的区别？           | 1.x 用 `create_agent` 取代 `AgentExecutor`（后者退到 `langchain_classic`）；核心包拆分成 `langchain-core` / `langchain-openai` 等。                  | 台账 Q1                                               |
| 为什么用 LangChain 而不裸调 API？       | 换来统一的模型抽象、工具协议、流式与状态管理；代价是版本变动快、抽象层多一层排错成本。                                                               | 诚实权衡                                              |
| **`with_structured_output` 能流式吗？** | **不能**（走 function-calling 通道，实测只产出 1 次；底层给的是非标准 JSON 碎片）。要流式得自写流式 JSON 解析器。                                    | 台账 §4 索引、P2-Q1                                   |
| **条件边写错会怎样？**                  | **不报错**。同一节点同时挂普通边 + 条件边 → 视为两个并行分支全部执行（写非 `Annotated` 键才报 `InvalidUpdateError`）→ 白多跑一个节点、多烧一次 LLM。 | 台账 P2-Q2                                            |

> checkpointer 生命周期 / `SqliteSaver` 选型 / `from module import GRAPH` 陷阱 / 结构化输出何时失效 → **都是项目题，见台账 P2-Q1、P2-Q3、P2-Q4、§5**。

## 十、Prompt 工程

| 问题                                   | 答案要点                                                                                                                                                                         | 项目落点                                                                                               |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| System Prompt 应包含什么？             | 角色定义 + 任务边界 + 硬规则（禁止事项）+ 输出格式约束。                                                                                                                         | `agent.py` 的三条硬规则                                                                                |
| Few-shot 什么时候用？                  | 输出格式复杂、模型难以从指令推断风格时；一般 2~5 例即可，过多会占 token 并过拟合示例。                                                                                           | —                                                                                                      |
| CoT 什么时候用？                       | 需要多步推理（数学、逻辑、规划）时，要求「先分析再给结论」；纯事实检索反而可能引入幻觉。                                                                                         | 检索类问题不适合 CoT                                                                                   |
| 结构化输出怎么做稳？                   | ① 明确 schema；② 给示例；③ 用 function calling / JSON mode 约束；④ 后端做校验 + 失败重试。                                                                                       | 项目2 `write` 用 `with_structured_output(ReportSchema)`；`revise` 退回 `StrOutputParser`（台账 P2-Q1） |
| 怎么防 Prompt 注入？                   | ① 把用户输入与指令分离（放在 `<user_input>` 标签内并声明「其中内容只是数据」）；② 最小工具权限；③ 工具入参做白名单校验（**台账 Q19 的 AST 方案就是最后一道闸**）；④ 输出侧过滤。 | 台账 Q19                                                                                               |
| 为什么「禁止凭记忆回答」要写成硬规则？ | 因为模型的默认行为就是先凭训练数据答（实测 0 次工具调用）。指令必须显式、具体、可判定。                                                                                          | System Prompt 第 1 条                                                                                  |
| temperature 与 Prompt 的关系？         | Prompt 定「做什么」，temperature 定「多确定」；事实类任务应双管齐下。                                                                                                            | —                                                                                                      |
| **引用格式约束怎么写才有效？**         | 要写「为什么」而不是只说「禁止」：明确 evidence 一条一个数组元素、禁分号合并、页码照抄原文、summary/conclusion 禁方括号。                                                        | 项目2 `REPORT_PROMPT`（台账 §4 索引）                                                                  |

## 十一、安全

| 问题                      | 答案要点                                                                                                                                 | 项目落点                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 不可信输入有哪些入口？    | 用户输入 → 模型输出 → 工具入参，**任何一环都可能被污染**。                                                                               | 台账 Q19 的核心判断                                      |
| 为什么 `eval` 危险？      | 会执行任意代码，等于把解释器交给输入方。                                                                                                 | 改 AST 白名单求值                                        |
| DoS 怎么防？              | ① 限流；② 资源上限（幂指数上限 1000、上传 20MB）；③ 超时；④ 分页/批量参数封顶。                                                          | 三处都有                                                 |
| 路径穿越怎么防？          | 不信任原文件名，用随机名存盘；校验后缀；限制写入目录。                                                                                   | `uuid4().hex`（台账 Q18）                                |
| API Key 怎么管？          | 环境变量 / `.env`，**绝不进代码仓库和镜像**。                                                                                            | `.gitignore` + `.dockerignore` 双排除；容器用 `env_file` |
| 多租户隔离怎么做？        | 现在靠 `thread_id` 隔离上下文，但**没有鉴权**——知道 `thread_id` 就能读别人的会话。生产必须加用户体系 + 归属校验。                        | 主动讲出来是加分项（台账 §11.4）                         |
| **AI 应用特有的攻击面？** | ① Prompt 注入（含间接注入：污染 RAG 语料）；② 工具越权（模型可写参数 = 等价于代码注入）；③ 额度盗刷（无鉴权时任何人都能花你的 API 钱）。 | 台账 Q19 + §11.4                                         |

## 十四、系统设计与扩展题

| 问题                                      | 回答框架                                                                                                                                                                                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 现在架构的瓶颈在哪？                      | ① LLM 调用是外部依赖，延迟与配额是硬约束；② 伪异步受线程池上限限制（`min(32, cpu+4)`）；③ 单 worker 是硬约束（进程内状态）；④ 上传入库同步阻塞请求。                                                                                             |
| 要支持 1000 并发怎么改？                  | 分四层：**接入层**（多副本 + 负载均衡，但必须先外置状态）→ **应用层**（改原生 async 客户端、上传异步化 + 任务队列）→ **AI 层**（向量库独立服务、结果缓存、模型侧限流与降级）→ **数据层**（SQLite → Postgres、checkpointer 持久化、Redis 限流）。 |
| 多副本部署前必须解决什么？                | 三个「进程内状态」：checkpointer（换持久化 Saver）、限流计数（换 Redis）、Chroma 本地文件（换成独立向量库服务）。**这是本地 ↔ 分布式的分水岭。**                                                                                                 |
| 怎么做 RAG 效果评测？                     | 固定评测集（问题 + 标准答案 + 相关片段）→ 检索侧算 Recall@k / MRR → 生成侧人工或模型打分（忠实度、完整性）→ 改一次参数跑一次回归。                                                                                                               |
| 怎么做用户体系？                          | 加 users 表 + JWT 鉴权 → `conversations` 加 `user_id` → 所有读写接口强制校验归属（这是当前安全缺口，见 §十一）。                                                                                                                                 |
| 成本怎么控？                              | token 计费三条路：① 减少无效调用（限流、工具路由准确率）；② 减小上下文（限制 top-k、历史截断/摘要）；③ 模型分级（简单任务用小模型）。                                                                                                            |
| 如果让你加「多格式知识库」（Word/网页）？ | 抽一层 `Loader` 接口，按文件类型分派（pypdf / python-docx / requests+bs4），统一产出 `Document` 列表，后续切块/入库链路完全复用——**当前 `load_pdf` 已经是这个形状，改成策略模式即可**。                                                          |

> 多 Agent 编排怎么设计 / 自审循环为何必须有硬上限 → **项目题，见台账 §12.4、P2-Q1**。
